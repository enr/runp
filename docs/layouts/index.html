01 what runp is

The system as a whole

Describe every part of your project — applications, services, tunnels — as units in one Runpfile and start them together.

Not just containers

Like docker-compose, but units can be host processes, containers or SSH tunnels, mixed freely.

Fast environment setup

Replace custom scripts and tribal knowledge with a single file anyone on the team can run.

02 capabilities

Per-unit setup

Working directory and environment variables for every process.

Variables

User defined vars in the Runpfile or passed at runtime with --var.

Await & readiness

A unit can wait for a file, a TCP port or another unit being ready before starting.

Startup ordering

Explicit ordering between units via depends_on.

One shot commands

Not only long running processes: run setup commands alongside services.

Secrets

Keep encrypted values in the Runpfile with runp encrypt.
